# Module reference

What each module of the gateway does, file by file. The invariants every change must keep (routing, tenancy, connection model, secondary resilience, trace archiving) live in [`AGENTS.md`](../AGENTS.md#architecture); read this page when working on a module.

Modules in `src/`, bundled by `vp pack` into CommonJS `dist/index.cjs` (entry `src/index.ts`; `ws`, `mongodb` and Node built-ins stay external; the dynamically imported `trace/mongo-store.ts` and `monitoring/sentry.ts` become their own chunks in `dist/`). A second `vp pack` config builds the viewer page from `web/viewer/` into `dist/viewer/`; the Docker runtime image still copies `dist/` only:

- **`index.ts`** — entrypoint: load config → set log level → open the error reporter when enabled (first, so startup failures are reported; they flush it before exiting) → load the route table (**fail-fast** if missing/invalid; backend ids required when archiving or when the viewer is enabled) → read the viewer page from `dist/viewer/` when enabled (fail-fast) → start watching it for hot reload → open the trace archive when enabled → start the gateway (exiting with 1 if it cannot listen) → start the viewer when enabled (same) → wire `SIGINT`/`SIGTERM` to a graceful shutdown (`gateway.close()`, which tears sessions down synchronously, then the live hub's close (so final delivery updates are still streamed), the archive's bounded flush and the viewer's close, then the error reporter's).
- **`config.ts`** — reads env vars (`PORT`, optional `LISTEN_HOST` (unset: all interfaces), `ROUTES_FILE` default `./routes.json`, `LOG_LEVEL`, `LOG_DEBUG_MESSAGE_MAX_LENGTH`, `MAX_MESSAGE_BYTES` default 1 MiB, optional `TENANT_BASE_DOMAIN` and `TENANT_HOST_HEADER`, optional session limits `MAX_SESSIONS`/`MAX_PENDING_SESSIONS`/`MAX_SESSIONS_PER_SOURCE` and `CLIENT_IP_HEADER` (unset: unlimited, socket address), `CHARGER_PING_INTERVAL` seconds → `chargerPingIntervalMs` (0, the default: no ping), `TRACE_*` → `config.trace`, undefined when archiving is disabled, `SENTRY_*` → `config.sentry`, undefined without `SENTRY_DSN`; the release defaults to the `package.json` version, and `VIEWER_*` → `config.viewer`, undefined unless `VIEWER_ENABLED=true`: `VIEWER_USERNAME`/`VIEWER_PASSWORD` required and taken verbatim, `VIEWER_HOST` default `127.0.0.1`, `VIEWER_PORT` default 9001 and never `PORT`, `VIEWER_MAX_BUFFERED_MESSAGES`, `VIEWER_MAX_CLIENTS`, `VIEWER_CLIENT_IP_HEADER`). Throws on invalid values (never echoing `TRACE_MONGODB_URI`, `SENTRY_DSN` nor the viewer credentials). No CSMS URLs live here anymore — those are in the routes file.
- **`routes.ts`** — the routing layer. Pure functions `parseRouteTable` (validates structure, throws on error), `resolveRoute(table, tenantId, id)` (`chargers[id]`, then the longest matching `"<prefix>*"` pattern, then `default`, within the tenant's scope, or the global scope for `null`; `null` when nothing matches; scopes use `Map`s), `isScopeEnabled(table, flag, tenantId)`/`disabledScopes(table, flag)` (the per-scope `trace` and `viewer` switches; `RouteStore` wraps them as `isTraced`/`untracedScopes` and `isViewed`/`unviewedScopes`), and `buildTargetUrl` (appends the url-encoded chargeBoxId to a backend URL, trims trailing slashes, keeps query params — unless the backend sets `appendChargeBoxId: false`). `RouteStore.load(path, { requireBackendIds })` loads the file (the option also applies to every reload), resolves routes and explicit tenant hostnames (`findTenantByHostname`, an index built at parse time), and optionally `watch()`es for hot reload (a failed reload keeps the previous table).
- **`proxy.ts`** — HTTP server (`GET /healthz` → 200) + `WebSocketServer`. Negotiates the OCPP sub-protocol, extracts the chargeBoxId from the **last path segment** of the request URL (URL-decoded), resolves the tenant from the host header (`Host`, or `TENANT_HOST_HEADER`; must be sent exactly once, otherwise the connection is closed with 1008 — **fail closed**, never routed globally) via a `TenantResolver`, resolves the route via the `RouteStore` (closing with 1008 when there is none), resolves the client source (`CLIENT_IP_HEADER` exactly once, or the socket address, keyed by `clientSource` in `utils/ip.ts`: a bare IP, IPv4-mapped → IPv4, IPv6 per /64; anything else → 1008, fail closed), checks the `SessionLimiter` as if the same-credentials stale sessions it would replace were gone (`SessionRegistry.replaceable`; closing with 1013 before any upstream dial, leaving those sessions running; throttled `RejectionLog`), only then evicts them, and spawns one `ChargerConnection` holding a `SessionLease` (released in `onEnd`, pending until `onPrimaryOpen`). Every refusal goes through `refuse()`, which adds an `error` listener and cuts the socket once the client sends more than a close frame or after 1 s, so a refused client can neither crash the gateway nor make it buffer a message. Logs the resolved route on connect. `startProxy(config, routes, { tenants?, traceSink? })` returns `{ server, close() }`; it registers no process handlers, so tests can start and stop gateways freely (see `test/helpers.ts`).
- **`tenants.ts`** — the `TenantResolver` interface (`resolve(host) → TenantId | null`), `parseHostname` (strict, no port — config and routes file), `normalizeHostname` (`Host`-header value: strips the port), `readSingleHeader`, and `HostnameTenantResolver` (explicit hostnames from the routes file first, then `<label>.<TENANT_BASE_DOMAIN>`). Framework-free: nothing Cloudflare-specific lives in `src/`.
- **`limits.ts`** — framework-free admission control: `SessionLimiter` (global, pending and per-source counts; `check(source)` → reason or `null`, `acquire(source)` → idempotent `SessionLease`; per-source entries deleted at 0) and `RejectionLog` (first rejection per (reason, source) logged at once, repeats summed per interval, bounded with a per-reason overflow bucket).
- **`sessions.ts`** — `SessionRegistry`: live sessions per `SessionKey` `{ tenantId, chargeBoxId }`, used by `proxy.ts` to replace a reconnecting charger's stale session (same credentials only), and to tear every session down on shutdown (`teardownAll`).
- **`connection.ts`** — the core. `ChargerConnection` takes a resolved `Route` and owns the full lifecycle of one charger session and all its upstream links. It has a `sessionId` (UUID) and, given a `TraceSink`, a `SessionTracer`. Forwards pings and pongs end to end and terminates the charger when a link holds more of them than `MAX_PENDING_FORWARDED_CONTROL_FRAMES` not yet written out.
- **`trace/`** — trace archiving, framework-free except `mongo-store.ts` (the only file importing `mongodb`):
  - `frame.ts` (`parseOcppFrame`: OCPP-J → Open OCPP Trace fields, or an unparsed reason), `record.ts` (record/document types — `OcppTraceRecord` is core's `TraceRecord` narrowed to what the gateway always sets —, delivery statuses and their rank; `SCHEMA_VERSION` and `Direction` come from `@open-ocpp-trace/core`), `correlator.ts` (per-conversation CALL ↔ response pairing, bounded by count and size);
  - `session-tracer.ts` (`SessionTracer`: one document per received frame, `fromCharger`/`fromPrimary`/`fromSecondary`, monotonic `DeliveryTracker`s);
  - `writer.ts` (ports `TraceSink`/`TraceStore`; `BufferedTraceWriter`: bounded queue, background batches, retries, counters), `mongo-store.ts` (`MongoTraceStore`: mapping, TTL and query indexes checked before every batch (recreated if the collection was dropped; options that narrow an index rejected), optional capped-collection requirement (`requireCapped`, never creates the collection), idempotent inserts, guarded delivery updates, BSON size fallback), `archive.ts` (`openTraceArchive`, lazy-loads the store).
- **`viewer/`** — the live trace viewer's own HTTP server (`VIEWER_HOST:VIEWER_PORT`, apart from the OCPP port):
  - `auth.ts` (framework-free: `parseBasicAuthorization`, strict RFC 7617; `verifyBasicAuthorization`, both parts always compared in constant time; `AuthFailureLimiter`, fixed window per source, bounded map whose overflow bucket fails closed, unref'd timer);
  - `server.ts` (`startViewer(config, { assets, next?, events?, authLimits? })` → `{ server, close() }`: security headers on every response, source from `VIEWER_CLIENT_IP_HEADER` exactly once or the socket address (else 400), 429 while blocked, then Basic auth on every route (401), then 405/404; `GET /`, `/viewer.js`, `/viewer.css`, and `/events` through the optional `events` handler; with `next` (the experimental page), `/next/`, `/next/viewer.js`, `/next/viewer.css`, and `/next` → `308 Location: next/` (relative); never logs credentials; `close()` drops open connections);
  - `hub.ts` (`LiveTraceHub`, the live `TraceSink` behind `GET /events`: `active()` while a client is connected; `insert` serialises a document once into an SSE `trace` event (no SSE `id`: no history to resume) written to every client, `updateDelivery` → `delivery` `{ id, index, delivery }`, `hello` on connect, `: ping` every 15 s from one unref'd timer, nothing retained; per-client bounds on `writableLength` sized from `MAX_MESSAGE_BYTES`: drop and count above the soft one or when an event would cross the hard one (checked before writing, never ending the client for it), `gap` `{ dropped }` once caught up, destroy at `maxDroppedEvents` drops in a row or after `maxDroppingMs` of dropping; counters `sent`/`dropped`/`endedSlow`; `503` over `maxClients`; `close()` ends every stream and logs the counters; never throws into the forwarding path);
  - `assets.ts` (`loadViewerAssets(dir)`: reads `index.html`, `viewer.js`, `viewer.css` once at startup from `dist/viewer/` (`index.ts` passes `join(__dirname, "viewer")`, next to the bundle, then `join(__dirname, "viewer-next")` for the experimental page); a missing file fails fast, naming it).
- **`web/viewer/`** (outside `src/`) — the viewer's browser page, type-checked by `tsconfig.web.json` (DOM libs, no Node types) and built by the second `vp pack` config into `dist/viewer/` (`app.ts` → one minified iife `viewer.js`, `index.html` and `viewer.css` copied):
  - `sse.ts` (`SseParser`, incremental WHATWG event-stream parser over decoded text; `id`/`retry` fields ignored);
  - `model.ts` (DOM-free: wire types derived from `src/trace/record.ts` with ISO-string dates, `decodeEvent`, `summarize` → `RowSummary`, `syntheticStatus`, `TraceStore` (buffer of trace and gap entries bounded by count and by `MAX_BUFFERED_BYTES` of raw frames, delivery merge by `(id, index)` forward-only, merged gap markers, `received`/`evictedMessages`/`evictedGaps`/`sessions` counters, `clear()`; `pause()`/`resume()`: entries created while paused are held apart within the same bounds (`pendingMessages`, `pendingDropped`, `isPending`), delivery updates applying to them too; `observed()`/`observedVersion`: the distinct tenants, charge points, actions and sources of the buffered messages), `FilterState`/`EMPTY_FILTER`/`filterPredicate` (AND of the filters, gap markers always pass, free text over metadata only), `jsonlLines(entries, "trace" | "frame")` → `{ lines, skipped }` (one part per line; trace records through `@open-ocpp-trace/jsonl`'s `serializeRecord`, an invalid one skipped and counted) and `exportFilename`, `ConnectionMachine` (states and jittered backoff), `STATE_LABELS`/`connectionMessage`, `EXPORT_WARNING`, `responseFailure`);
  - `stream.ts` (`startLiveStream`: `fetch("/events")` + `ReadableStream`, 401 stops, everything else retried; DOM-free, tested in Node, also against a real gateway);
  - `highlight.ts` (JSON highlighting with [Prism](https://prismjs.com) (`prismjs`, MIT, a **devDependency bundled into `viewer.js`**, never a runtime dependency of the gateway): core + JSON grammar only (`prism-global.ts` gives the grammar its global `Prism`, `prismjs.d.ts` types the component imports), manual mode, `Prism.tokenize` tokens turned into spans and text nodes through a `Builder`; never Prism's HTML highlighters; plain text above `HIGHLIGHT_MAX_CHARS`);
  - `app.ts` (DOM glue only: `createElement`/`textContent`, one DOM update per animation frame, detail built on selection, a delivery update refreshing only its Deliveries section; a filter change rebuilds the list from `store.entries()` on the next frame, a delivery update under a delivery filter inserts or removes only that row; exports through `download.ts`'s `saveJsonl` (`Blob` + a temporary `<a download>`, shared with `web/viewer-next/`) after a `window.confirm` raw-data warning); `index.html`, `viewer.css` (no inline script nor style: the viewer's CSP).
  - `test/viewer/web-safety.test.ts` keeps HTML and code sinks (`innerHTML`, `eval`, inline handlers, Prism's `highlight*`…) out of these sources.
- **`web/viewer-next/`** — the experimental page on the [Open OCPP Trace viewer](https://github.com/open-ocpp-trace/viewer) (`@open-ocpp-trace/viewer-standalone`, a devDependency bundled into its `viewer.js`, React included; from GitHub Packages like the SDK), built by the third `vp pack` config into `dist/viewer-next/`, served under `/next/`. It reuses `../viewer/stream.ts`, `sse.ts`, `download.ts` and `model.ts` (`decodeEvent`, `ConnectionMachine`, wire types, connection and export texts) and adds only:
  - `mapping.ts` (`gatewayEntry`: a document → a viewer entry, `record` = `doc.trace` untouched, frames → `unparsed`; tenant, charge point, session (= `conversationId`), source, deliveries as metadata; seq/correlation/ignored/binary in `custom`);
  - `feed.ts` (`createGatewayFeed`: the `ViewerAdapter`, empty snapshot; per-id delivery states in a FIFO bounded at 2 × the first hello's `maxBufferedMessages`, updates by `(id, index)` applied forward only by `DELIVERY_STATUS_RANK` and emitted as metadata `update`s; `gap` → `dropped` gap with `missedCount`, a reconnection → `disconnected`, a restart → `restarted`, dated at the first loss);
  - `app.ts` (mounts the viewer on the first `onConnected` with `maxEntries` = `maxBufferedMessages`; stream URL `../events`, relative; connection state and the feed's and `getStats()` counters through `textContent`); `index.html` and `viewer.css` with relative URLs. Tests: `test/viewer/web-next/`.
- **`logger.ts`** — structured JSON logging to stdout (stderr for errors), filtered by level. Each connection logs under a tag = chargeBoxId (`tenantId/chargeBoxId` within a tenant); `debugOcppFrame` logs OCPP frames at debug level, truncated to `LOG_DEBUG_MESSAGE_MAX_LENGTH`. `configureLogger` accepts an injectable sink (tests silence it in `test/setup.ts`) and an `ErrorReporter`: `log.error(msg, extra, { report: true, cause })` also reports the error (best-effort, never throws); a plain `log.error` is only logged, and `cause` alone adds its message as the `error` field.
- **`error-reporter.ts`** — the `ErrorReporter` port (`report` synchronous and non-throwing, `close(timeoutMs)` bounded and idempotent) and `noopErrorReporter`. Framework-free.
- **`monitoring/sentry.ts`** — `openSentryReporter`, the only file importing `@sentry/node`: errors only (`defaultIntegrations: false` — no http breadcrumbs nor sessions — with uncaught exception, unhandled rejection in `strict` mode so the process still crashes, linked errors, dedupe, node context), `dataCollection` all off, and a `beforeSend` running `redactUrlsInText` over messages, exceptions, fingerprints and extras. `test/monitoring/sentry.test.ts` checks, through a recording transport, that nothing else (breadcrumbs, sessions, credentials of the gateway's own WebSocket traffic) is sent. `test/process.test.ts` builds the bundle and runs it as a process against a local Sentry ingest: exit codes, crash and startup-failure reports, flush on shutdown.
- **`utils/`** — `value-parsers.ts` (env parsing used by `config.ts`) and `websocket.ts` (`forwardPing`/`forwardPong`, capped per target socket by `MAX_PENDING_FORWARDED_CONTROL_FRAMES` and returning `sent`/`skipped`/`over-cap`; `rawDataToString`), both from upstream; `bounded-queue.ts` (`BoundedQueue`, the upstream replay queues bounded by count and bytes; `push` returns the evicted messages); `url.ts` (`redactUrl`, `maskUserinfo`, `redactUrlsInText`); `ip.ts` (`clientSource`, the per-source limit key); `secrets.ts` (`constantTimeEqual`, SHA-256 + `timingSafeEqual`, shared by `sessions.ts` and the viewer's auth); `errors.ts` (`errorMessage`), `objects.ts` (`isPlainObject`), `text.ts` (`hasControlCharacter`, shared by `config.ts` and the viewer's auth), `ocpp.ts` (`isOcppResponse`: CALLRESULT/CALLERROR, type id as a number or a decimal string).
- **`types.ts`** — OCPP message-type constants and the sub-protocol preference list (`ocpp2.0.1` > `ocpp2.0` > `ocpp1.6`).
